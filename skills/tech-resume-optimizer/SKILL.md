# Technical Resume Review


Use the supplied resume, career evidence and target role. Return specific improvements with evidence IDs or source references; ask only for material missing facts. For a complete rebuild use the sibling resume-builder workflow.

Review these dimensions:
- Ownership: distinguish implementation, co-design, integration, coordination and formal management.
- Engineering: identify architecture decisions, constraints, data/API contracts, failure modes and actual deployment responsibilities. A technology list alone does not demonstrate depth.
- Production: explain scale as product context unless personally attributable; distinguish observability usage from building observability infrastructure, and staging replays from production validation.
- Applied AI: distinguish retrieval, tool orchestration, evaluation and agent operations from model training/research. Clarify where frameworks run instead of combining them into an inaccurate architecture.
- Leadership: show decisions adopted, teams influenced and sustained effects. Assignment of tickets or small-project leadership alone does not establish staff scope.
- Forward deployment: show discovery, integration constraints, shipped workflow, adoption and support; preserve internal versus external customer boundaries.
- Relevance: prioritize the strongest demonstrated capabilities for the supplied job; do not add unconfirmed skills.

Return a short fit assessment, prioritized repairs and only the unanswered questions that change positioning. Do not certify seniority or replace historical job titles.
