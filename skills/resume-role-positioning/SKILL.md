# Role positioning

Use the career bank as the shared source of truth. Differentiate the variants by which evidence leads and which details explain it, while retaining identical underlying dates, titles, metrics, and project status.

Read [references/role-signals.md](references/role-signals.md) for the selected tracks. Role signals are editorial lenses, not universal hiring rules. A supplied job description takes priority. If researching live role expectations, read current employer postings and label interpretations; do not rely on remembered postings.

For each target, state the strongest supported value proposition, select the best accomplishments, and identify evidence missing for a credible claim. Prioritize relevance, ownership, technical depth, outcome, recency, and distinctiveness. Do not score likelihood of an offer.

For a job description, build a compact matrix: requirement; required/preferred/unclear; evidence ID; demonstrated experience; resume placement; gap or limitation. Preserve distinctions between production experience, prototype use, and transferable skills. Do not insert a technology just because the employer asks for it.

Use a functional qualifier alongside the official employment title when needed. The headline may name the target role, but historical roles must not imply an unearned promotion. Senior/staff calibration depends on scope and influence, not simply years or having coordinated several engineers. Distinguish reusable architecture adopted across teams from routine delivery coordination.

Write a short selection rationale per variant so future tailoring preserves the reasoning. Keep omissions in the master evidence bank even when irrelevant to this application.
