# Resume Bullet Writer


Start from source facts or the career bank, not an impressive-sounding example. Draft around action, technical mechanism and outcome/scope in whichever order reads clearly. Use direct verbs matched to actual responsibility; co-designed, contributed and fixed can be accurate even when a checker dislikes them.

For weak bullets:
1. Identify the user's personal action and the problem it addressed.
2. Identify what changed, including credible qualitative outcomes.
3. Include a number only when its value, unit, population and basis are supplied or defensibly estimated by the user. Do not require a number in every bullet.
4. Keep attribution explicit: measured before/after, monitored in production, user-reported, estimated or a target.
5. Remove repeated architecture context, jargon and filler without deleting the engineering mechanism.

Read [references/metric-integrity.md](references/metric-integrity.md) when a result uses percentages, time savings, adoption counts or failure rates.

Return proposed bullets with evidence IDs and a concise explanation of any changed attribution. If asked to invent an incident or metric, provide a clearly hypothetical interview prompt, never insert it as experience. Reconcile a user's correction with older variants before delivery.
